```css
  --down: #a01519;   /* PnL negatif, stance SHORT, ask, loss     5.17:1 */
  --hold: #7f4500;   /* stage stalled/halt, risk, spread lebar   4.91:1 */
  --info: #0d5177;   /* struktur pasar: node agen/feed, sumbu     5.49:1 */

  --z-plot-under: 0;  /* .ob-bar */
  --z-plot-over:  1;  /* teks orderbook */

```

Rasio terukur terhadap ketiga permukaan (terlemah di `--bg-app`): `ink-0` 12.05 · `ink-1` 6.42 · `ink-2` 4.70 · `up` 5.10 · `down` 5.17 · `hold` 4.91 · `info` 5.49. Semua ≥ 4.5:1. Putih di atas `--up`/`--down`/`--hold` = 7.92 / 8.03 / 7.63, jadi badge terisi tetap terbaca. Yang sekarang gagal: `--green-neon #009933` 2.72, `--amber-warning #c27800` 2.55, `--red-alert #d02020` 3.89.

**Aturan warna:**

1. **Merah = rugi, di mana pun.** Chip stance `#cc3333` dan `--red-alert #d02020` runtuh ke `--down`.
2. **State tidak pernah pakai opacity pada teks.** `opacity:0.45` di atas `#ede4cc` composite ke 2.25:1 — itu grifos satu-satunya yang_dialogue scanner strip. Abstain = `--ink-2` full opacity + border dashed + `—`.
3. **Isian = token yang sama pada alpha 10–18% atas `--bg-inset`.** Tidak ada hex kedua. Bar orderbook adalah bentuk, bukan teks, jadi tidak butuh 4.5:1.
4. **Hijau = PnL positif ATAU stance LONG. Tidak ada hijau lain.** `#009933`, `#00e650`, `#00ff66` (header tag), `rgba(184,72,…)` (glow) semuanya hilang.
5. **Tidak ada warna dekoratif.** Border panel, tag header, dan chip netral tidak membawa hue.
6. **Nol hex di luar blok `:root`.** Lint: `grep -nE '#[0-9a-f]{3,6}' dashboard/assets/style.css` → hanya boleh hit di dalam blok `:root`. Saat ini ada 30 hex di body aturan dan `#000` hardcoded 40×.
7. `hud_figures.py` mengimpor enam nilai yang sama; `INK_MUTED = "#665e4e"` dihapus (tidak ada di token mana pun).

## STRUCTURAL TRAPS THE SPEC MISSES

**1. `className` Outputs destroy layout classes.** 15 Outputs write `className` directly. `hud-giant-pnl`'s callback (line 667) returns `"giant-pnl text-green"` — hardcoded. The spec §2 keeps `hud-giant-pnl` but §3 shrinks the hero to 30px via a CSS class while §6 lists `giant-pnl` as a class to be *removed*. If `giant-pnl` leaves CSS, the 500ms callback keeps writing the class name and the element falls back to `--fs-3` 12px. Same trap for `hud-scanner-consensus` (line 779 writes `"odds-consensus-badge stance-long"`) and all 6 tree nodes + 5 arrows + rail (lines 1334-1346, which emit `tree-step-node tone-blue stage-done` etc. as literal strings). The spec's §2 table correctly keeps 13 tree IDs "resolvable" but never notes that **their styling depends on callback-authored class names that the spec's CSS rewrite must keep in exact syntactic form**. `test_layout_contract.py` does not cover this — it checks IDs, not emitted class strings.

**2. `hud-tree-flow-rail-fill` has both a `className` Output and a `style` Output.** The spec §3A folds the rail into the 44px strip as an "underline 2px at the band base". Worse: `style` Output **replaces the entire style dict**, so if the spec adds `height`/`background` to that div inline in `hud.py`, the callback destroys it on the first tick. This is the sharpest trap in the codebase and the spec never mentions it.

**3. `align-items: start` breaks the spec's own `.p-stack` flex math.** §1 sets `align-items: start` on the container (correct, and it does fix the 40% wallet gap — measured `.wallet-box-content` is 32px tall with `scrollHeight=148`, i.e. **116px of content clipped by `overflow:hidden` today**). If a child ever wraps or the scanner's content exceeds 181px, the `min-height:0` stack lets the *inner* `.hud-panel-body` overflow instead of growing the row, because `align-items:start` means the grid row height is set by the tallest item and `.p-stack` has no `height` guarantee of its own outside the 356px token.
